# STANDARD — generate packets for ANY group set (the fork contract)

The UPG-100 machinery is generative: point the packet generator at **one folder** and it produces
a packet per list, localized, with no code change and no `series.json` edit. This document is the
contract; `internal/check-group-set-standard.mjs` is its falsifier (a synthetic 3-list toy set runs
end-to-end on every gate pass, so the contract cannot rot silently).

## What a fork supplies — one folder

```
my-set/
  clusters.json           REQUIRED  the group-set file (schema below)
  records.json            OPTIONAL  your own people rows — with it, no API and no cache are needed
  selector-evaluator.js   REQUIRED  resolvable from the folder (re-export ours, or ship your own)
  normalize.js            OPTIONAL  absent -> records are used as-is (logged once, never silent)
  legend-tree.js          ONLY for the bucketed legacy shape; a flat set never needs it
```

### clusters.json — the generic (flat) shape

```json
{ "lists": [
    { "id": "my-north", "label": "My North", "selector": { "type": "pg_slugs", "values": ["a","b"] } },
    { "id": "my-draft", "label": "Draft",    "unlisted": true, "selector": { … } }
] }
```

- `selector` — any type your evaluator handles (`pg_slugs` needs nothing but slugs).
- `unlisted: true` — defined and selectable with `ONLY=<id>`, but not generated by default.
  This is the reachability idea as data.
- The bucketed shape (`lists` + `asia_lists` + `uncovered_lists` + `deaf_lists`) is the UPG-100
  catalogue's legacy form; its enumeration goes through the legend tree to keep the deaf collapse.
  New sets use the flat form.

## Running it

```
DATA_DIR=path/to/my-set PACKET_OUT=out/my-packets PACKET_LANG=es node library/scripts/posters/packet.mjs
ONLY=my-north …          # one list        NOPHOTOS=1 …   # skip photo fetch
```

- **Locale**: `PACKET_LANG` (never the shell's `LANG`); strings come from `packet-strings.json`
  per-locale blocks with per-key fallback — a new language is a new block, not a code change.
- **Titles**: the per-list `label` + your strings block. Nothing else to configure.
- `PACKET_OUT` keeps fork/test output away from the real artifact directory.

## Pages that depend on optional repo data (they omit cleanly, never fail the run)

| page | needs | absent → |
|---|---|---|
| map (page 1) | `out/posters/<id>.html` (`bun run posters`) | cover without the map |
| triangle | `data/people-groups/vision-funnel.json` | page omitted |
| %-evangelical | `data/people-groups/christian-share.json` | page omitted |
| bounded/centered sets | `public/dx-maps/assets/tables/near-neighbors.json` joined by slug | page omitted |

A fork's first run therefore yields: cover + profiles (+ triangle if the repo file is present) —
correct and smaller, per the rule that a page which cannot state true numbers must not appear.

## Not in scope

Posters for arbitrary sets (the poster generator needs geo/bbox inputs this contract does not
define yet), multi-territory maps, and authoring UI. The in-app catalogue is the plugin's own
`data/clusters.json` — a fork edits its copy; the file is the interface.
